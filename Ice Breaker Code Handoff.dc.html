4 · Matching/schedule gaps — already identified in docs/HANDOFF.md, still open

These aren't new findings — HANDOFF.md's 2026-07-28 entry already logs them as "not built this pass." Repeating them here because they're the highest-leverage remaining work and belong in one place with everything else.

FileGapFix
app/actions/admin.ts (matchOneSlot) + lib/matching.tsNo schedule filter exists at all. event_id/stay_start/stay_end are collected (0009) but never read by matching — two people who picked different events, or whose stay dates don't even overlap the slot's date, can still land in the same signup list and get seated together.Two explicit stages, in order: (1) filter signups to the slot's event_id and to signers whose [stay_start, stay_end] covers the slot's date — a hard constraint; (2) run matchSlot's interest-based packing only on survivors of (1). lib/matching.ts (matchSlot)Skips the LLM (and therefore interests) whenever a slot's total headcount ≤ 6 — the common case for a small dinner — falling to interest-blind roundRobinGroups.Run the interest-aware LLM path even for single-table slots; reserve pure round-robin for genuine API failure only.
lib/matching.ts (matchSlot)A failed validateAssignment after 2 LLM retries re-packs the entire slot via round-robin, discarding any groups that were already valid.Keep valid groups from the failed attempt; only re-pack the invalid ones.
